# Complete recipe: 2D Poisson on a TPZGenGrid2D structured mesh

Canonical flow for solving `-∇²u = f` on a structured grid generated by
`TPZGenGrid2D` — the generator most NeoPZ unit tests (`TestReducedSpace`,
`TestHCurl`, `TestHDivApproxSpaceCreator`, SBFem tests) still use.

## When to use which generator

- **`TPZGeoMeshTools::CreateGeoMeshOnGrid`** — the modern convenience: one
  call creates the mesh **and** the boundary elements, but with a single
  boundary material id.
- **`TPZGenGrid2D`** — more control: `SetElementType` switches between
  quadrilaterals and triangles, `SetBC` gives **each of the 4 edges its own
  material id** (sides 4..7 of the quadrilateral domain), and
  `SetRefpatternElements`, `SetDistortion`, `SetZigZagPattern` and
  `SetGeometricProgression` shape the grid. Older but still everywhere in
  the test suite.

## Step by step

1. **Generator** — `TPZGenGrid2D gen(nx, x0, x1)` (include
   `"TPZGenGrid2D.h"`): `nx` = divisions per direction, `x0`/`x1` = the
   lower-left/upper-right corners with **2 coordinates** (not the 3-coords
   convention of `CreateGeoMeshOnGrid`).
2. **Element type** — `gen.SetElementType(MMeshType::EQuadrilateral)` (or
   `ETriangular`).
3. **Fill a mesh** — `auto *gmesh = new TPZGeoMesh; gen.Read(gmesh, EDomain);`
   — `Read` already calls `SetDimension(2)` and `BuildConnectivity()`
   internally, do not call them again.
4. **Boundary elements** — `gen.SetBC(gmesh, side, EBC)` for `side` in
   `4..7` (the four edges of the quadrilateral domain). There is also a
   `SetBC(gmesh, start, end, bc)` overload taking node coordinates.
5. **The rest is the standard skeleton** — `CreateCMesh` (H1, material with
   `EDomain`, BC with `EBC`), `SolveProblem` (`ELDLt` + `SetNumThreads`),
   `PrintResults` (`TPZVTKGenerator`, `"Solution"`/`"Derivative"`).

## Complete code (compilable)

```cpp
#include "pzgmesh.h"            // TPZGeoMesh
#include "TPZGenGrid2D.h"       // TPZGenGrid2D
#include "MMeshType.h"          // MMeshType::EQuadrilateral
#include "pzcmesh.h"            // TPZCompMesh
#include "Poisson/TPZMatPoisson.h"  // TPZMatPoisson<STATE> (current API — family prefix!)
#include "TPZLinearAnalysis.h"  // TPZLinearAnalysis
#include "pzskylstrmatrix.h"    // TPZSkylineStructMatrix
#include "pzstepsolver.h"       // TPZStepSolver
#include "pzmanvector.h"        // TPZManVector
#include "pzfmatrix.h"          // TPZFMatrix
#include "pzvec.h"              // TPZVec
#include "TPZVTKGenerator.h"    // TPZVTKGenerator (post-processing to .vtk)
#include <string>

enum EMatid { ENone, EDomain, EBC };   // material ids: 0 is never used
constexpr int nThreads{4};             // number of threads for assembly and post-processing

TPZGeoMesh *CreateGMesh(int nDiv);
TPZCompMesh *CreateCMesh(TPZGeoMesh *gmesh, int pOrder);
void SolveProblem(TPZLinearAnalysis &an, TPZCompMesh *cmesh);
void PrintResults(TPZCompMesh *cmesh, const std::string &plotfile);

int main() {
    constexpr int pOrder{2};
    TPZGeoMesh *gmesh = CreateGMesh(8);
    TPZCompMesh *cmesh = CreateCMesh(gmesh, pOrder);
    TPZLinearAnalysis an(cmesh);
    SolveProblem(an, cmesh);
    PrintResults(cmesh, "gengrid2d");
    delete cmesh;
    delete gmesh;
    return 0;
}

// ── Geometric mesh — structured grid via TPZGenGrid2D ─────────────────────
TPZGeoMesh *CreateGMesh(int nDiv) {
    // x0/x1 have 2 coordinates here (x, y) — NOT the 3-coords convention of
    // CreateGeoMeshOnGrid
    const TPZManVector<int, 2> nx = {nDiv, nDiv};
    const TPZManVector<REAL, 2> x0 = {0., 0.};
    const TPZManVector<REAL, 2> x1 = {1., 1.};
    TPZGenGrid2D gen(nx, x0, x1);
    gen.SetElementType(MMeshType::EQuadrilateral);  // or ETriangular

    auto *gmesh = new TPZGeoMesh;
    gen.Read(gmesh, EDomain);  // Read already sets dimension + connectivity

    // Sides 4..7 are the 4 edges of the quadrilateral domain — this is what
    // makes GenGrid2D handy: each side can get its own material id
    for (int side = 4; side < 8; side++) {
        gen.SetBC(gmesh, side, EBC);
    }
    return gmesh;
}

// ── Computational mesh + material + boundary ─────────────────────────────
TPZCompMesh *CreateCMesh(TPZGeoMesh *gmesh, int pOrder) {
    const int dim = gmesh->Dimension();  // 2, set by Read
    auto *cmesh = new TPZCompMesh(gmesh);
    cmesh->SetDimModel(dim);
    cmesh->SetDefaultOrder(pOrder);
    cmesh->SetAllCreateFunctionsContinuous();  // continuous H1 approximation

    // Material — ALWAYS on the heap (the mesh takes ownership)
    auto *mat = new TPZMatPoisson<STATE>(EDomain, dim);
    mat->SetForcingFunction(
        [](const TPZVec<REAL> &loc, TPZVec<STATE> &result) {
            result[0] = 1.;  // f(x,y) = 1
        },
        pOrder);
    cmesh->InsertMaterialObject(mat);

    // Homogeneous Dirichlet boundary condition (type 0)
    TPZFMatrix<STATE> val1(1, 1, 0.);
    TPZManVector<STATE, 1> val2 = {0.};
    auto *bnd = mat->CreateBC(mat, EBC, 0, val1, val2);
    cmesh->InsertMaterialObject(bnd);

    cmesh->AutoBuild();  // without it the computational mesh stays empty
    return cmesh;
}

// ── Assemble and solve ────────────────────────────────────────────────────
void SolveProblem(TPZLinearAnalysis &an, TPZCompMesh *cmesh) {
    TPZSkylineStructMatrix<STATE> strmat(cmesh);
    strmat.SetNumThreads(nThreads);
    an.SetStructuralMatrix(strmat);
    TPZStepSolver<STATE> solver;
    solver.SetDirect(ELDLt);  // symmetric system — the standard direct solver
    an.SetSolver(solver);
    an.Assemble();  // Solve does NOT assemble
    an.Solve();
}

// ── Post-processing (VTK for Paraview) ────────────────────────────────────
void PrintResults(TPZCompMesh *cmesh, const std::string &plotfile) {
    constexpr int vtkRes{1};
    TPZVec<std::string> fields = {"Solution", "Derivative"};
    auto vtk = TPZVTKGenerator(cmesh, fields, plotfile, vtkRes);
    vtk.SetNThreads(nThreads);
    vtk.Do();  // writes <plotfile>.0.vtk
}
```

## Common mistakes

- **`x0`/`x1` with 3 coordinates** — `TPZGenGrid2D` takes 2-entry corners
  (`{0., 0.}`, `{1., 1.}`); the 3-coords convention belongs to
  `CreateGeoMeshOnGrid`.
- **`SetDimension`/`BuildConnectivity` after `Read`** — unnecessary: `Read`
  does both internally.
- **`SetBC` before `Read`** — the boundary sides do not exist until the
  elements are generated; call `SetBC` after `Read`.
- **Sides `0..3` in `SetBC`** — those are corner nodes; the four edges of
  the quadrilateral domain are sides `4..7`. (The header comment says
  `0 <= side < 4` — the actual tests all use `4..7`.)
- **A single boundary id when edges differ** — that is the reason to choose
  GenGrid2D at all: call `SetBC` per side with different ids.
- **Material on the stack / forgetting `AutoBuild` / `Solve` without
  `Assemble` / `DefineGraphMesh`** — same pitfalls as the Poisson recipe
  (post-processing goes through `TPZVTKGenerator`).
